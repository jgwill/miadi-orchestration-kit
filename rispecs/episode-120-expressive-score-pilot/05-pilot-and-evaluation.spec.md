# 05 — Pilot and evaluation

## Technical proof

- offline capture continues while event delivery spools locally;
- requested and observed sensor rates remain distinct;
- signed clock drift is recorded against a named reference;
- sha256 identifies every transported artifact reference;
- partial-channel recovery preserves the truthful channel state;
- unordered exact duplicates replay idempotently;
- event gaps and conflicting revisions fail closed;
- traversal, absolute paths, file/data/blob URLs, media bytes, participant
  words, unknown fields and secret-bearing refs are refused;
- Git contains no raw media, credentials or local custody paths.

## Separate human judgments

1. Participant or keeper accepts, refuses or holds the proposed custody/use.
2. Independent evaluator judges technical reliability.
3. Creator/composer accepts, refuses or holds musical usefulness.
4. Editor/director separately accepts or refuses timeline placement.

No majority vote or automated score collapses these decisions.

## Pilot yield

T10 may be proposed for formalization only when all five proofs exist together:

1. one verified expressive take;
2. one linked composition;
3. one timeline placement;
4. one recorded human decision set;
5. one replayable receipt.

T3's creator-experience record and T1's resumable handoff are required closure
evidence. A software test suite alone leaves the pilot open.

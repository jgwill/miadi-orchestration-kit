Who owns each step

Authorship · ep019's P3

Who wrote a mark, decided in one place

The route already applies this order (app/api/tide/annotate/mark/route.ts:63-67, and :87 for the refusal). Core exports it as resolveAuthor(), so the route and every other host apply the same rule. The evidence (a token, a tailnet header) stays with each host.

  1. 1
    Signed token. The person the token belongs to is the author. A different author in the body is refused with 409.
  2. 2
    Asserted by the host. In Miadi, a tailnet identity on the request.
  3. 3
    Typed in the form. Remembered per browser, used only when it is a valid { id, name }.
  4. 4
    None of these. Refused with 400, "author required". Marks made before attribution existed show as "unsigned".
Figure 4 · The iPhone selection fix

Why the fix belongs in core

iOS clears a text selection as soon as anything outside it is touched, so by the time a button's click runs, getSelection() is already empty. Today's fix (reply-annotator.tsx:208-241) is plain DOM: a selectionchange listener, a containment check and a grace window. Core exports it as captureSelection() so a non-React page gets it too (P1, C5).

// app/api/tide/annotate/mark/route.ts calls resolveAuthor({ signed, asserted, typed })
// and resolveQuote(doc text, quote): a quote found more than once is refused with
// "these words appear N times in the reply; select a longer phrase" (D3)
// components/tide/reply-annotator.tsx after A8 (sketch): same props as today
export function ReplyAnnotator({ paneId, accent, onDelivered, replyEpoch = 0, following = false }: Props) {
  const transport = useMemo(() => httpAnnotateTransport({
    urls: {
      load: "/api/tide/annotate/resolve",
      mark: "/api/tide/annotate/mark",
      marks: doc => `/api/tide/annotate/marks?doc=${encodeURIComponent(doc)}`,
      deliver: "/api/tide/annotate/deliver",
    },
    bodies: { load: { pane: paneId }, deliver: submit => ({ pane: paneId, submit }) },
  }), [paneId])
  const identity = useCockpitIdentity()     // Miadi: /api/identity/me + "tide.annotate.author"
  const { graceMs } = useTideConfig()       // Miadi: MIADI_TIDE_ANNOTATE_GRACE_MS, read on the server per request
  const ctl = useRef<AnnotatorController>(null)
  useTurnFollow(ctl, replyEpoch)            // Miadi: reload until the text changes, keep undelivered marks
  return <Annotator transport={transport} identity={identity} theme={{ accent }} graceMs={graceMs} controllerRef={ctl}
    onDelivered={o => o.submitted && onDelivered?.()}
    renderFooter={s => <DeliverFooter paneId={paneId} state={s} following={following} />} />
}

Risks

What could go wrong, and what prevents it

R1

Wrong publish order

npm's @miadi/tide@0.4.0 predates annotate. Publishing tide before core, or reusing 0.4.0, ships a package that points at the wrong code. Prevented by the A9 order and its verify step.

R2

The two renderers drift

React output and plain HTML could diverge over time. Prevented by the parity test in A7, as attention-ui already does.

R3

Quote context promises more than the server does

plannotator-tui --annotate marks the first occurrence (Q1). Handled by D3: a quote whose place is not the first occurrence is refused, never misplaced, until N2 lands.

R4

Scope growth

Packaging the pane cards or the inspector at the same time would double the work. They stay out, as listed under Architecture.

Decided · revision 2

Decisions and answers

Each card says who decided it. D1 and D4 are yours. The others you left to me, and each card gives the reasoning so you can overrule any of them before the build reaches it.

D1
approved by you

Package names

@miadi/annotate-core and @miadi/annotate-ui. Both were free on npm when checked on 2026-09-23.

D2
decided by Claude, as you asked

resolveAuthor lives in core

The rule is short, pure and security-relevant, so it should exist once. The Miadi route imports it, and markRequest on the client is built from the same rule, so the two sides cannot disagree about who wrote a mark. Evidence (the token, the tailnet header) never enters core. It stays with each host. This also answers Q5.

D3
decided by Claude, from the Q1 research

Quotes carry context, and an ambiguous quote is refused

QuoteSelector (exact, prefix, suffix, as in the W3C annotation model) goes in core now, and captureSelection fills in the prefix and suffix from the selection. resolveQuote finds exactly one place or says why not. Until plannotator can take a range (N2), Miadi passes a quote only when its place is the first occurrence. Otherwise the mark is refused with "these words appear N times in the reply; select a longer phrase". A mark is never silently attached to the wrong sentence.

go from you · waiting on the review agent

Q1
answered by research

plannotator marks the first occurrence

add_quote_annotation runs source.find(quote), so a repeated phrase always lands on its first occurrence. Its internal annotate(range) already takes a byte range, so exposing a range on the command line is a small upstream change (N2).

miadisabelle/mia-plannotator-tui crates/plannotator-tui/src/app/mod.rs:550-555 · plannotator-tui 0.6.0
Q2
decided by Claude, as you asked

The route types stay out of tide-contract

A contract package should cover one boundary between parties that deploy separately. @miadi/tide-contract is the Miadi ↔ IronSilk runtime contract, with a schema and a drift check. The annotate routes are Miadi's own HTTP surface over plannotator, and IronSilk doesn't implement them. Their vocabulary lives in annotate-core. Revisit only if the IronSilk runtime starts serving annotate.

Q3
your direction

gmtermux gets the minimum

The work goes into making the packages reusable and published. gmtermux gets only the wiring that proves it can load them, plus an issue there listing what they make possible, so the choice of what to annotate is made later (A10).

Q4
answered · decided by Claude, as you asked

1500 ms was chosen, and it becomes a server setting

It came from the phone fix in commit 6d6cb033 (jgwill/Miadi#381, 2026-09-13), which says "kept for 1.5s". No measurement is recorded. Core takes graceMs (default 1500). Miadi reads MIADI_TIDE_ANNOTATE_GRACE_MS on the server for each request, so a restart changes it without a rebuild. Values outside 0–10000 fall back to 1500. The name is your …GRACE_PERIOD with the unit in place of "period", so nobody has to guess whether it means seconds or milliseconds.

answered by D2

See D2.

Later phases · N = next-phase outcome

Kept so they aren't lost, not built now

N1

Annotations belong to an episode

From your /chronicle comment: marks made on a reply or a chapter can be attached to an episode and read from its vessel, optionally. The packages already carry what this needs (AnnotateDocument.id, StoredMark with its author). The episode link belongs in @miadi/episode-vessel and the chronicle, not in annotate-core.

N2

plannotator takes a range

An --annotate-range flag (or equivalent) in miadisabelle/mia-plannotator-tui, opened as an issue in that repo first. Then resolveQuote's position is passed straight through, and D3's refusal is lifted for repeated phrases.
